# YottaWeave

面向开发工作的智能体平台：把技能、记忆、编排、校验、安全做成一套能长期干活的工程链。

> 本仓库只分发安装包，不含源码。

---

## 组成

| 层 | 内容 |
| --- | --- |
| **元技能操作系统** | **32 个技能**（记忆 / 编排 / 呈现 / 校验 / 安全 / 授权测试 / 开发工具 / 沉淀），27 个默认启用 |
| **运行期插件** | **11 个插件**，在真实会话里守边界：会话上下文、输出瘦身、验证回环、子代理护栏、仓库模型、压缩保留、危险调用拦截 |
| **产品面** | 界面与交互、提示词与协议、默认目录、能力中心、装配器、权限策略、更新链 |
| **数据** | 离线优先：记忆与配置留在本地（`%USERPROFILE%\.yottaweave`），记忆库可 diff、可回滚 |

## 它和单兵式工具有什么不同

大多数编程智能体是**单兵**：一个模型、一个上下文、一套工具，干完就走。

YottaWeave 补的是一条**分层的工程链**：

- **编排**：任务拆解 → 按依赖串行 / 并行派子代理 → 主代理只做判断，不做搬运；
- **记忆**：跨会话（FACT / PREF / BOUND / COMMIT 四类），开工恢复上下文，收工落盘，不用你复述；
- **自证**：每条结论要求**证据**（命令输出 / 测试 / 哈希 / 截图），并按「已验证 / 未验证 / 无法验证」三态标注 —— 不许把「写完了」说成「能用了」；
- **守边界**：权限、作用域、出口闸门由代码判定，不由模型自觉。

## 三道锁（可直接验证）

1. **网络出口有闸门**：接口调用与 shell 里的 `curl` / `wget` / `ssh` 走**同一套判定** —— 私有网段（`10/8`、`172.16–31`、`192.168/16`）需审批，云元数据地址 `169.254.169.254` **直接拒绝**，连「允许一次」都不给。
2. **审批带范围**：点一次「总是允许」只记住**那一个来源**（`scheme://host:port`），不会放行全部目标。
3. **作用域默认收窄**：问「上次说到哪」只读**当前项目**状态；问「装了哪些技能」只报**本产品**的；读**项目目录之外**的路径弹审批并写明原因。

被拒后**不换通道**（不改写命令、不换 `Invoke-WebRequest`、不用内置抓取）—— 换通道等于绕过。

## 安装

到 [Releases](../../releases) 下载最新的 `yottaweave-desktop-*-win-x64.exe`，双击安装。

- **仅为我安装**（per-user），无需管理员权限；数据目录 `%USERPROFILE%\.yottaweave`
- 平台：Windows x64
- 覆盖安装保留配置与记忆；需要干净重建时删除 `%USERPROFILE%\.yottaweave\config`（不动记忆库）

校验：

```powershell
Get-FileHash .\yottaweave-desktop-<版本>-win-x64.exe -Algorithm SHA256
```

每个 Release 都写明大小与 SHA-256。

## 边界

- **面向开发**，但不禁你顺手写方案、做报告、查资料 —— 「专注开发」是默认重心，不是能力许可证。
- **越界请求先问授权**：渗透测试 / 批量爬取 / 对第三方系统操作，先确认目标与授权范围再动手。
- **不做关键词拦截**：按「目标」判定而不是按「危险词」—— 否则写安全用例、补防护、审依赖全被误伤。
- **shell 网络识别是尽力而为**：变量拼接、命令替换、base64、脚本内部发请求无法识别。目标是**抬高绕过成本并让动作可见**，不是绝对阻止。
